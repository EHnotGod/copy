# R² 为什么"涨点却不给力"？—— μ/τ 分解实验

## 直觉

现有 3-tier 数据里每 sample 有三档真值 $y_{i,t} = \{y_{i,10}, y_{i,50}, y_{i,\text{tts}}\}$。可以拆成：

$$
y_{i,t} \;=\; \underbrace{\mu_i}_{\text{prompt 整体难度（三档均值）}} \;+\; \underbrace{\tau_{i,t}}_{\text{step 相对增益（三档中心化残差）}}
$$

同理 predictor 输出 $p_{i,t}$ 也能拆成 $\hat\mu_i + \hat\tau_{i,t}$。

- **R²_total** = R²(p_flat, y_flat)：主指标（3N 个点）
- **R²_μ** = R²($\hat\mu$, μ)：predictor 学 prompt 难度学得多好（N 个点）
- **R²_τ** = R²($\hat\tau$_flat, τ_flat)：predictor 学 step-wise 增益学得多好（3N 个点）
- **baseline μ_only**：predictor 只输出 $\hat\mu_i$（τ 强制置 0），R²_total 上就相当于"完全无视 step 差异，只按 prompt 难度打分"

dp 决策需要的是**同一 prompt 内选哪档 step 最好**——这只依赖 τ，跟 μ 无关（μ 对同一 prompt 三档都一样，在 argmax 里抵消）。

如果 R² 涨主要来自 μ、τ 学不到，那 R² 涨点但 dp 不涨就完全合理。

## 实验

Predictor = **Qwen3-8B + Ridge**（exp1.1 里最强），score 模式直接输出三档绝对分。
Train pool = gen 400 + gen2000 拼接的 2400 池，按 LC sizes 100/300/600/1000/1500/2200 训。
Test = raw 800，两版数据（GM / AM）都做。

## 结果

### GM 版

**qwen**：

| n | R²_total | R²_μ | R²_τ | R²_μ_only (baseline) |
|---:|---:|---:|---:|---:|
| 100 | +0.127 | +0.065 | +0.254 | +0.044 |
| 300 | +0.270 | +0.231 | +0.350 | +0.155 |
| 600 | +0.350 | +0.352 | +0.345 | +0.237 |
| 1000 | +0.401 | +0.416 | +0.372 | +0.279 |
| 1500 | +0.399 | +0.412 | +0.371 | +0.277 |
| 2200 | **+0.411** | **+0.437** | +0.359 | +0.293 |

- R²_total 从 0.13 涨到 0.41（**Δ = +0.28**）
- R²_μ 从 0.07 涨到 0.44（**Δ = +0.37**）—— **就是 R²_total 涨的来源**
- R²_τ 从 0.25 → 0.36（Δ = +0.11，n=600 已经饱和，剩下就没动过）
- baseline μ_only 到 n=2200 的 R² = 0.293（真 predictor 0.411）—— 真 predictor 里 **约 71% 的 R² 单靠输出 $\hat\mu_i$ 就能刷到**

**flux**：

| n | R²_total | R²_μ | R²_τ | R²_μ_only |
|---:|---:|---:|---:|---:|
| 100 | +0.263 | +0.320 | **−0.184** | +0.284 |
| 300 | +0.368 | +0.433 | **−0.132** | +0.383 |
| 600 | +0.384 | +0.450 | **−0.134** | +0.399 |
| 1000 | +0.437 | +0.507 | **−0.106** | +0.449 |
| 1500 | +0.471 | +0.541 | **−0.075** | +0.480 |
| 2200 | **+0.495** | **+0.567** | **−0.072** | **+0.503** |

- R²_total 从 0.26 涨到 0.50（Δ = +0.24）
- R²_μ 涨 +0.25，跟 R²_total 涨幅**几乎完全对应**
- **R²_τ 全程为负**（predictor 输出的 τ 比乱猜零还差）
- baseline μ_only R² = **0.503 ≥ 真 predictor 0.495**——**真 predictor 输出 τ 反而拉低了整体 R²**

## 结论

**R² 涨点几乎完全来自 μ_i（prompt 整体难度），τ_{i,t}（step 相对增益）predictor 根本学不到，甚至反向。**

具体：

1. **R²_total 涨 ≈ R²_μ 涨**（qwen +0.28≈+0.37，flux +0.24≈+0.25）
2. **R²_τ 早饱和或全程为负**（qwen n=600 饱和 0.35；flux 全程 −0.07 ~ −0.27）
3. **μ_only baseline** 已经能刷到真 predictor R² 的 71%（qwen）到 100%+（flux）
4. dp 决策的 argmax 只看同 prompt 内三档相对大小、跟 μ 无关，所以 R²_τ 没涨 → dp acc 没涨 → 完全一致

**"R² 涨了但 dp 不涨" 不是矛盾，是 predictor 只学 μ 不学 τ 的直接后果**。加数据能提升 μ 的估计精度（→ R²_total 涨），但 τ 是 prompt 里无法直接预测的东西（同一 prompt 换 step 数会不会突然变好，这跟 prompt 语义关系很弱），所以 dp 决策一直卡住。
