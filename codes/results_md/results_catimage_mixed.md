## 为什么做不好 —— 判别器基本没干活

先看每档 fixed 分和 oracle 的距离（geneval2 为例）：
- 5 档 fixed = [25.20, 24.21, 24.82, 31.63, 33.21]，档间跨度 8 分
- oracle = 46.59（逐条选最优）→ oracle 比最好的单档还高 **13.4 分**
- 说明"逐条挑对档位"这件事本身有巨大空间

再看**判别器的实际预测行为**（full-train，从 preds_geneval2_full.json 抽样）：

| 指标 | KNN | TFMLP | 真实值 |
|---|---|---|---|
| 预测 5 档跨档 std（每条 prompt 内的方差）| 0.025 | 0.041 | 0.135 |
| 逐 prompt Spearman(预测,真实) | 0.155 | 0.123 | — |
| KNN 选择分布 [qw10, qw50, fx10, fx50, fx4b] | [43, 0, 62, **684**, 11] | | |
| TFMLP 选择分布 | [23, 249, 94, 317, 117] | | |
| Oracle 选择分布 | [118, 136, 173, 241, 132] | | |

**问题很明显**：

1. **预测跨档方差比真实低 3-5 倍**（KNN 0.025 vs 真实 0.135，TFMLP 0.041 vs 0.135）—— 判别器几乎对每条 prompt 输出"5 档差不多"的 flat 预测，只是全局 mean 差了一点点
2. **逐 prompt Spearman 只有 0.12-0.18** —— 五档的相对次序基本是**瞎猜**（0 是完全无关，1 是完美）
3. **KNN 800 条里 684 条都选 flux9b_50**（85%），几乎退化成一个 "永远选最贵" 的常量策略（真 oracle 只在 30% 上选这档）
4. **TFMLP 完全不选 qwen_10**（0 条），把它当成"从不最优"的档位 —— 但 oracle 上它是 15% 最优

wise 更极端：TFMLP Spearman **0.039**（近似随机），KNN 也就 0.125。所以 KNN/TFMLP 在 wise 上和 LP 打平，不是"追平"，是**两边都在瞎猜**。

对照 coco：Spearman KNN=0.313 / TFMLP=0.342（三个 bench 里唯一还像样的），但**5 档真实值本身太接近**（跨档 std 只有 0.041 = 2/3 wise 或 geneval2），学到的信号也换不成质量增益。

## 根因

**信号从 prompt → 5 档质量本来就弱**：
- CLIP text encoder 冻结，只 fine-tune 2 层 transformer + MLP 头（原论文架构）
- 训练集才 400 条（in-domain）或 2000 条（full），5 档全监督
- 5 档里 qwen_10 和 qwen_50 只差 step 数、prompt 侧几乎看不出哪个更适合；flux9b_10 / flux9b_50 同理
- **真正区分度大的档**（flux4b_4 便宜差、flux9b_50 贵优）在 prompt 层面也没稳定 pattern —— 一句 "红球在蓝盒左边" 到底哪档更好取决于图像生成的随机 seed，不是 prompt 本身

**所以现状是**：判别器学到了一点弱信号（Spearman 0.1-0.3），argmax 出来的选择又受 fixed cost 惩罚推着往 fx9b_50 集中（cost=115.5，λ 稍高就退到 fx9b_10 或 tts），最终 quality@50 只能微超或不超 LP。

## 要提升，需要

1. **加图像 side 特征**：光看 prompt 无法预测生成质量，必须看到某档生成出来的粗略草图（early-step preview）或每档的 CLIP 一致性分
2. **换更强的 predictor**：现有 2-layer transformer + 400 训练样本，容量和数据都太小；要么换 pretrain 的 reward model，要么把训练集扩到 10k+
3. **改成 pairwise 或 ranking loss**：现在 BCE 让每个头独立回归归一化质量，天然不擅长学"5 档相对排序"；直接 ranking loss + margin 会更对齐 argmax
