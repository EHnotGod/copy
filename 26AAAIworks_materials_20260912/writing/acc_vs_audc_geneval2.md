# 为什么 ACC 高、AUDC@50 反而不高：geneval2 上 TFMLP 的严谨拆解

## 现象

geneval2 的 in-domain 结果里有一处看着矛盾的地方：

| 方法 | AUDC@50（分数） | ACC（命中率） |
|------|----------------:|-------------:|
| LP（盲基线） | **34.83** | 31.5% |
| KNN@50 | 35.90 | 47.2% |
| TFMLP@50 | 34.76 | **50.2%** |

TFMLP 的命中率（50.2%）几乎是 LP（31.5%）的 1.6 倍，可最终分数（34.76）却比 LP（34.83）还低一点。命中率遥遥领先、分数却垫底。下面用逐条数据把原因拆开，不做笼统断言。

以下所有数字来自 geneval2 in-domain（test N=800，train pool=1200，seeds 0/1/2，与 `run_catimage_router.py --indomain` 完全一致的采样与训练流程）。

---

## 事实 1：真实最优档（不看成本）的分布——tts 占了一半

对每条 prompt 取"质量最高的档"作为 oracle 标签（不考虑成本），800 条测试样本的分布：

| 真实最优档 | 计数 | 占比 |
|-----------|-----:|-----:|
| qwen_10 | 73 | 9.1% |
| qwen_50 | 72 | 9.0% |
| flux9b_10 | 144 | 18.0% |
| **qwen_tts** | **402** | **50.2%** |
| flux4b_4 | 109 | 13.6% |

tts 在恰好 50.2% 的 prompt 上是真实最优档。记住这个 50.2%。

---

## 事实 2：TFMLP 的 argmax 决策——三个 seed 都把每一条判给 tts

三个 seed 的 TFMLP 预测 argmax 分布，完全一致：

```
seed0: ACC=50.2%  argmax = {qwen_10:0%, qwen_50:0%, flux9b_10:0%, qwen_tts:100%, flux4b_4:0%}
seed1: ACC=50.2%  argmax = 同上
seed2: ACC=50.2%  argmax = 同上
```

三 seed 合并的混淆矩阵（行=真实最优档，列=TFMLP 的 argmax 预测，共 800×3=2400 条）：

| 真实＼预测 | qwen_10 | qwen_50 | flux9b_10 | qwen_tts | flux4b_4 | 行合计 |
|-----------|--------:|--------:|----------:|---------:|---------:|-------:|
| qwen_10 | 0 | 0 | 0 | 219 | 0 | 219 |
| qwen_50 | 0 | 0 | 0 | 216 | 0 | 216 |
| flux9b_10 | 0 | 0 | 0 | 432 | 0 | 432 |
| qwen_tts | 0 | 0 | 0 | **1206** | 0 | 1206 |
| flux4b_4 | 0 | 0 | 0 | 327 | 0 | 327 |
| 列合计 | 0 | 0 | 0 | 2400 | 0 | |

每档的 precision / recall：

| 档 | recall | precision | 被预测次数 |
|----|-------:|----------:|-----------:|
| qwen_tts | 100.0% | 50.2% | 2400 |
| 其余四档 | 0.0% | 0.0% | 0 |

**ACC 命中来源分解**：总命中 1206 次，其中 100.0%（1206/1206）来自 tts 这一档，非 tts 档命中 0 次。

也就是说，TFMLP 的 50.2% ACC **完全等于 tts 在测试集里的占比 50.2%**——这不是巧合，而是"把每条都判给最常赢的 tts"的直接算术后果。ACC 因为不看成本、只问 argmax 猜没猜中，把这种"单押最热门档"的策略打了满分。

---

## 事实 3：光看 argmax 会漏掉真相——连续预测分数其实是有微弱信号的

你提醒得对：不能只看 argmax 分类结果。λ-sweep 真正用的是**五维连续预测分数** `rs_tf`，决策是 `argmax(pred − λ·cost)`，argmax 只是 λ=0 时的特例。所以要看连续分数本身。

**每档"预测分数 vs 真实分数"的 Spearman 相关**（seed0）：

| 档 | Spearman ρ | 预测值 std | 真实值 std |
|----|-----------:|-----------:|-----------:|
| qwen_10 | +0.465 | 0.031 | 0.260 |
| qwen_50 | +0.464 | 0.029 | 0.257 |
| flux9b_10 | +0.540 | 0.031 | 0.291 |
| qwen_tts | +0.474 | 0.042 | 0.285 |
| flux4b_4 | +0.582 | 0.037 | 0.294 |

**每档预测分数的取值范围**：

| 档 | min | mean | max | std |
|----|----:|-----:|----:|----:|
| qwen_10 | 0.037 | 0.076 | 0.138 | 0.031 |
| qwen_50 | 0.043 | 0.081 | 0.138 | 0.029 |
| flux9b_10 | 0.057 | 0.098 | 0.158 | 0.031 |
| **qwen_tts** | **0.098** | **0.157** | **0.231** | 0.042 |
| flux4b_4 | 0.036 | 0.081 | 0.157 | 0.037 |

两张表合起来说明两件事：

1. **每档单独看是有微弱信号的**（ρ≈0.46~0.58，都为正），TFMLP 并不是纯噪声——它对每一档"这条 prompt 大概能拿多少分"有一点粗略的感觉。
2. **但它给 tts 这一档整体加了一个很高的偏置**：tts 的预测均值 0.157，比其余四档（0.076~0.098）高出一大截，而各档预测值的 std 只有 0.03~0.04。**跨档的这个 0.06~0.08 的均值差，远大于档内 0.03 的波动。** 结果就是：无论哪条 prompt，tts 的预测分几乎总是压过其他档 → argmax 恒为 tts。

**关键点**：问题不在"每档预测得准不准"（每档 ρ 都还行），而在**跨档校准坏了**——tts 被系统性抬高，导致"哪档最好"这个跨档比较永远输出 tts。argmax 只是把这个偏置放大成了 100%。

---

## 事实 4：预算 50 一约束，信号立刻不够用

"tts 恒为 argmax"意味着 λ=0（不管成本）时全选 tts，平均成本 = 100（tts 单档成本就是 100），**是预算 50 的整整两倍**。（作为对照：oracle 按真实质量选，只有 50.2% 的 case 落在 tts，平均成本才 60.1；TFMLP 把剩下一半也押给 tts，成本直接顶到 100。）

在 AUDC@50 的横截面上（λ-sweep 扫到平均成本≈50 的点，实测 λ=0.0008、平均成本 49.8），路由器被迫从 tts 退下来：

- **此时实际档分布**：flux9b_10 53% / qwen_tts 37% / flux4b_4 10%
- **此时命中真实最优档**：从 50.2% 掉到 **25.0%**
- **此时平均质量（AUDC@50）**：35.48

一旦成本被卡住，argmax 那个 50.2% 的漂亮命中率直接腰斩到 25%。

**降档决策到底有没有信息量？** 在被迫弃用 tts 的 502 个 case 里，看 TFMLP 选中的便宜档是不是该 case"非 tts 四档中真实最优"的那个：命中率 **39.6%**（随机在 4 档里蒙的期望是 25%）。

这个 39.6% 是整件事的落点：TFMLP 在"负担不起 tts、必须退而求其次"时，**确实比瞎猜强一点（39.6% > 25%），但强得很有限**。因为它的信号几乎全花在"tts 最好"这一个粗判断上，对"当 tts 用不起时四个便宜档谁更好"只学到很淡的东西。所以降档后质量补不回来。

---

## 对比：LP 为什么在预算 50 处反而不吃亏

LP 从头到尾不看 prompt，只按训练集各档均分（qwen_10=7.31、qwen_50=7.46、flux9b_10=8.82、qwen_tts=13.81、flux4b_4=7.60，×100）在预算 50 处凑两档线性混合。它的 ACC 只有 31.5%——因为它根本不针对单条 prompt 挑档，argmax 层面当然猜不中。

但 LP 有一个结构性优势：**它花的每一分预算都稳稳落在"全局性价比最优"的档组合上，绝不会为了追 tts 而超支、再被迫降档去打那个 39.6% 的补救仗。** 所以在预算 50 这个真正结账的横截面上，它的分数（34.83）稳稳压过 TFMLP（34.76）。

---

## 结论

用逐条数据把因果链讲清楚：

1. **高 ACC 的来源是可算的**：TFMLP 的 50.2% ACC 恰好 = tts 在测试集的占比 50.2%，命中全部来自 tts 一档（1206/1206），本质是"单押最热门档"，而非会分辨 prompt。
2. **不是没信号，是跨档校准坏了**：每档预测 vs 真实的 Spearman ρ≈0.46~0.58（有微弱信号），但 tts 被系统性抬高 0.06~0.08（远超档内 0.03 的波动），使跨档比较恒输出 tts。
3. **预算约束是照妖镜**：全押 tts 平均成本 100（是预算 50 的两倍）> 预算 50，被迫降档后命中率 50.2%→25%，降档补救仅 39.6%（略胜瞎猜 25%），质量补不回来。
4. **ACC 会骗人，AUDC 才算数**：ACC 奖励"赌对最热门档"、无视成本；AUDC@50 惩罚"超预算后不会补救"。TFMLP 占了前者、栽在后者，所以 ACC 高而分数低。真正该看的是预算约束下的 AUDC，也就是 LP 这条盲基线设的坎。
