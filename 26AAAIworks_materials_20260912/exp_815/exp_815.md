## 实验一：直接预测 —— R² 虚高

做法：每个 dataset × cfg，用 train:2200 训练 predictor（val:200 选参/早停），在 test 上逐条预测 score，计算 R²。

- Predictor：Ridge（Qwen3-Embedding-8B）、KNN（CLIP mean-pool）、TFMLP（CATImage Appendix D）

### 核心现象

**R²(all) 普遍较高（0.2–0.5），但去掉 0/1 两端堆积样本后，R²(mid)（y∈(0.1,0.9)）大面积塌陷甚至为负** —— 全样本 R² 主要由极端样本贡献， predictor 对"中间样本"（真正需要区分的 query）几乎没有预测力。

## 实验二：带路由（score 模式，budgets = 5 / 10 / 20）

做法：Lagrangian 路由 `argmax(pred − λ·cost)`，quality@budget 线性插值，**三个 budget 档 5.0 / 10.0 / 20.0**（predictor 的 test 预测只算一次，三档复用）。Predictor：**Ridge**（Qwen3-Embedding-8B + StandardScaler，α∈{1,10,100,1000} 按 val R² 逐 cfg 选）、**KNN**、**TFMLP**（后两者为 CATImage predictor）；baseline：**always_qwen50**、**LP**（train 均值凸包两档混合）、**OC**（train oracle 分布随机分配）；**Oracle** 为上界参考。seeds [0,1,2] 报均值±标准差（Ridge/KNN 确定性，三次同值）。

costs = [2.0, 10.0, 4.7, 23.1, 4.3, 21.5, 0.455]（与路由池 7 cfg 同序）

always_qwen50 是 budget 无关常数（test 上 qwen50 列均值，自身 cost=10）；**budget=5.0 时它已超支，仅作锚点参考**，不参与可行解比较。

**结论**：

- **budget=5**（只有 flux4b/qwen10/flux10/boogu10 买得起，always_qwen50 自身成本 10 已超支、只是锚点）：三 predictor 仍大幅超过 OC 与超支锚点，但 gm 上 LP（0.358）反超三个 predictor（0.350–0.352）——极低预算下凸包混合已接近最优，predictor 的中间区间误差（实验一）在窄选择空间里被放大；unigen 上 Ridge 依然最强（0.892，Oracle 0.942）。
- **budget=10**：Ridge ≥ KNN > TFMLP 一致成立，且全部 ≥ LP/OC/always_qwen50；unigen Ridge 0.906 已接近 Oracle 0.943。
- **budget=20**：路由空间变大（可混入更多 50steps 档），但 gm/unigen 的 Oracle 已饱和（0.542→0.543、0.943→0.943），各方法增益收窄到 +0.01~0.02；排序出现交叉——gm/am 上 KNN 反超 Ridge（gm 0.381 vs 0.380；am 0.809 vs 0.803），unigen 上 Ridge 持平。LP 在三数据集上都仍是 baseline 里最强的，且在 gm 上超过全部 predictor（0.391 vs 0.377–0.381）。
- 总体：predictor 路由的增益主要来自中间 budget 区间；极低预算（5）下简单凸包混合已很难打，高预算（20）下质量饱和、差距收敛。与 Oracle 的剩余差距（gm 0.543 vs 0.381）正是实验一"R² 虚高、中间样本预测不准"的直接体现——predictor 还有明显提升空间。

## 实验三：掐头去尾（budget=10）

**动机**：实验一证明 R²(all) 主要由 0/1 两端堆积样本贡献。一个自然的假设是：把两端堆积样本从训练集里去掉，让 predictor 专注中间区间，路由可能变好。本实验直接验证。

**设计**：极端样本 = train pool 中任一 cfg 的 true score ≤0.05 或 ≥0.95（与分布图阈值一致）。去除比例 X ∈ {0%, 20%, 40%, 60%, 80%, 100%}，用 `np.random.default_rng(seed)` 随机移除极端样本中的 X%（0% = 完整训练集 baseline；100% = 只保留 7 cfg 全部落在 (0.05, 0.95) 的样本）。Ridge / KNN / TFMLP 在裁剪后的子集上训练（Ridge 的 α 选择、TFMLP 的早停仍用不裁剪的 val 200；TFMLP 的 min-max lo/hi 用裁剪后训练集），test 不变，只跑 budget=10。baselines（Oracle/LP/OC/always_qwen50）用完整训练集、固定为实验二 budget=10 的值作参照。seeds [0,1,2] 报均值±标准差（移除采样与 TFMLP 都按 seed）。frac=0 行与实验二 budget=10 的 Ridge/KNN/TFMLP 逐位一致（复现校验通过）。

- **GM**（极端样本高达 80.9%）：Ridge 从 0.377 单调降到 0.354（100%）；KNN 基本平（0.371→0.362，中段微降）；唯一亮点是 TFMLP 在 20% 去除时升到 **0.384**（+0.014，超过 0% 的 0.370，也超过同列所有 baselines），但 40% 后回落、100% 时崩到 0.345。峰值在 20%。

- 解读：两端堆积样本虽然对"中间区间拟合"没有帮助（实验一），但它们携带了**路由最需要的信号**——哪些 query 在哪个 cfg 上必死/必满分——去掉后 predictor 对 test 中同类极端样本的路由判断变差；同时训练集缩小本身也在伤性能。唯一正面结果是 GM/TFMLP/20% 的小幅提升，但幅度小（±0.005 量级）且不稳定，不足以支持"掐头去尾"作为改进方向。

## 实验五：Oracle gap 的反事实分解（budget=10）

动机：实验一发现 R² 虚高、中段 R² 塌陷（0/1 两端堆积撑起整体 R²）；实验三发现掐头去尾重训没用。那么路由相对 Oracle 的 gap 到底来自哪里——极端样本识别不准，还是中段排序错误？用反事实替换直接量化：把 test 中**极端样本**（真实 anchor qwen_50steps score ≤0.05 或 ≥0.95，对应实验一分布图的 0/1 堆积）或**中段样本**的 7 维预测换成真值，分别重算路由质量（λ 扫描 + 线性插值，与实验二完全同口径）。base 直接复用 `results/backup_exp5/exp5_preds/` 里 base 配置的 test 预测缓存。

## 实验六：两阶段 predictor（极端检测器 + 中段回归器，budget=10）

承接实验五：gap 的 76%~97% 在中段，且极端样本上各档质量差很小（am/unigen ≤0.07）——那把极端样本从回归任务中剥离、交给固定策略省钱，让回归器专心学中段，是否能改进路由？

做法：**第一阶段**用与 predictor 相同的输入特征训练 LogisticRegression 三分类器（near-0 / mid / near-1，标签按 train anchor 真实 score ≤0.05 / 中间 / ≥0.95；Ridge 管线用 Qwen3 emb，KNN/TFMLP 管线用 CLIP mean-pool）；**路由策略**——检测为极端的 test 样本固定分最便宜档 flux4b_4steps（cost=0.455；实现上把预测改成 one-hot，整个 λ 网格含 λ=0 下 argmax(pred − λc) 恒选 flux4b，口径与实验二一致），检测为中段的样本用**第二阶段回归器**（只在 train 中段样本上重训的 Ridge/KNN/TFMLP，alpha/k/归一化均按中段子集）正常路由。与实验三的区别：实验三把极端样本直接丢弃，这里极端样本由检测器+固定策略处理，中段由专门回归器处理。实验五的极端样本各档真实质量表支持这个固定策略：极端样本上最好档与最便宜档的质量差在 am/unigen 只有 ~0.07，省钱价值大于质量损失；gm 差 0.155 但成本差 47 倍。base 数字为实验二 budget=10，引用前已对备份缓存预测逐位核对（Ridge/KNN 全等、TFMLP 均值差 <1e-9）。

1. **检测器不够准**：gm/unigen 的 test 三分类 acc 只有 0.69~0.81；被误判为极端的中段样本（gm emb 检测器 105/800、unigen 40/600 条）被强制分最便宜档，这些样本恰是路由收益的主要来源，损失直接吃掉收益。am 的极端只有 36 条且几乎检测不出（emb 只抓回 4/36），两阶段几乎等于 base，自然持平。
2. **中段训练集缩小重演实验三的伤害**：第二阶段只用中段样本训练（gm 1225/2200、unigen 1560/2200），与实验三掐头去尾同构——实验三已证明去掉极端样本训练会伤路由（gm Ridge 0.377→0.354、unigen 0.906→0.865），这里的退步幅度与此一致。
3. **极端侧的天花板本来就低**：实验五已界定完美处理极端（含"知道谁是极端"的信息优势）只能补 gap 的 4%~26%，而本方案的固定策略连"给真值"都不如（极端样本拿的是最便宜档而非最优档），即便检测器完美也补不回中段回归的损失。

综合实验五/六：**改进路由的出路在中段排序**（如更好的中段相对质量建模），而不是"检测极端 + 特殊处理"的两阶段结构；极端样本按 anchor 阈值剥离对训练反而是净伤害。
