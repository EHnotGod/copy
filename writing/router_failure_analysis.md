# 面向文生图的学习式路由的能力边界：一项实证研究

## 实验二 —— 换成多个模型来路由，预测器就学不动了

### 1. 实验设置

实验一里，候选池是"同一个模型跑不同步数"。这次我们换掉它，用**五个来自三种不同模型的配置**组成候选池：

| 档位 | 配置 | 成本 $c_m$ |
|------|------|-----------:|
| A | FLUX-4B，4 步（蒸馏） | 2.3 |
| B | Qwen，10 步 | 10 |
| C | FLUX-9B，10 步 | 23.1 |
| D | Qwen，50 步 | 50 |
| E | FLUX-9B，50 步 | 115.5 |

路由器现在要决定的是**用哪个模型**，而不再只是**同一个模型跑多少步**。其余设置和实验一一样：预算限制 $C(r)\le 50$，对比 oracle、LP、OC、KNN、TFMLP 五种方法，seeds 0/1/2，四个 benchmark，分数 $\times 100$。

（名词：oracle = 开了上帝视角、每条 prompt 都选对的理论上界；LP、OC = 两个不看 prompt 内容、纯按预算凑档位的"盲"基线；KNN、TFMLP = 两个真的去看 prompt、学着预测该选哪个的模型。）

### 2. 结果：会学习的预测器，反而输给了瞎猜的基线

| benchmark | oracle@50 | **LP（盲）** | OC | KNN@50 | TFMLP@50 |
|-----------|----------:|-------------:|---:|-------:|---------:|
| geneval2 | 46.59 | **32.08** | 27.41 | 29.35 | 27.84 |
| corebench | 57.10 | **49.99** | 47.27 | 48.48 | 47.90 |
| wise | 86.61 | **75.71** | 73.64 | 74.64 | 74.37 |
| coco | 97.51 | **94.40** | 92.97 | 93.12 | 92.52 |

四个 benchmark 上，**会看 prompt 的路由器（KNN、TFMLP）全都输给了 LP**——而 LP 根本不看 prompt，只是为了满足预算把档位凑一凑。也就是说，让模型去看 prompt 内容、学着挑模型，不但没帮上忙，**反而帮了倒忙**。这和实验一正好相反（那里学习式的确赢过盲基线）。

差别不在于用了什么学习算法，而在于**这批"标签"本身有没有规律可学**。下面三节就来看这批标签到底出了什么问题。

### 3. 为什么学不动：没有一个主导的选择方向，几个模型还打成平手

**(a) 最优模型分散在五个档位里，没有哪个特别常赢。** 我们统计每个档位"成为某条 prompt 最优选择"的频率：

| benchmark | FLUX4B-4 | Qwen-10 | FLUX9B-10 | Qwen-50 | FLUX9B-50 | 最大 |
|-----------|------:|------:|------:|------:|------:|----:|
| geneval2 | 0.15 | 0.17 | 0.23 | — | 0.26 | 0.26 |
| corebench | 0.19 | 0.16 | 0.20 | — | 0.28 | 0.28 |
| wise | 0.21 | 0.16 | 0.21 | — | 0.23 | 0.23 |
| coco | 0.12 | 0.14 | 0.23 | — | 0.31 | 0.31 |

没有任何一个档位占多数，最优选择差不多是**平均分散**在各档上的（五个档平均分就是 $1/5 = 0.20$，实测最大也才 0.23~0.31）。

换个角度量化一下"到底有多平均"：如果最优档高度集中在某一个上，那"最优是哪个档"这件事就很好猜；如果五个档各占约 1/5，那基本就跟抛骰子一样没法猜。我们用一个 0 到 2.32 的打散程度指标来衡量（2.32 表示完全平均、最难猜）：

| benchmark | 打散程度（bits） | 最大值 | 占比 |
|-----------|-----------:|--------:|------:|
| geneval2 | 2.29 | 2.32 | 98.7% |
| corebench | 2.29 | 2.32 | 98.7% |
| wise | 2.31 | 2.32 | **99.6%** |
| coco | 2.24 | 2.32 | 96.6% |

四个 benchmark 都到了最大值的 96%~99.6%——**"最优模型是哪个"几乎跟随机一样没规律**。实验一那种情况不一样：那里有一条清楚的"这条 prompt 值不值得上 tts"的线，信号就落在这条线上；而这里没有任何一条这样的线能把档位分开。哪个模型最合适，取决于 prompt 和模型之间很细的"脾气对不对付"，对不上任何一个简单的排序。

**(b) 预测器给档位排的顺序，跟真实好坏对不上——这是"学不动"最直接的证据。** 对每条 prompt，我们比一比"预测器排的档位好坏顺序"和"真实的档位好坏顺序"有多吻合（$+1$ = 完全排对，$0$ = 跟乱排没区别，负数 = 排反了）：

| benchmark | 实验二 TFMLP | 实验二 KNN | | 实验一同任务 TFMLP |
|-----------|-----------:|---------:|---|-----------:|
| geneval2 | $-0.001$ | $+0.096$ | | geneval2_qwen $+0.381$ / _flux $+0.074$ |
| corebench | $-0.185$ | $+0.086$ | | corebench_qwen $+0.268$ / _flux $+0.155$ |
| wise | $-0.137$ | $-0.023$ | | wise_qwen $+0.457$ / _flux $+0.299$ |
| coco | $-0.384$ | $+0.096$ | | coco_qwen $+0.303$ / _flux $+0.164$ |

**实验一的排序一直是正的（$+0.07$ 到 $+0.46$，说明多少排对了一些），实验二则全都掉到 0 附近、好几处还是负的。** 负数更糟：意味着预测器不光没学到东西，还系统性地把好档排到了坏档前面。同一套预测器、同一批 prompt，只是把候选池从"单模型多步"换成"多模型"，排序能力就从正值归零了。这说明问题不在模型能力不够，而在于**这批标签本身就分不开**。

**(c) 几个模型在每条 prompt 上几乎打平，就算路由选得完美也没多少分可捞。** 我们看每条 prompt 上"最优档"和"次优档"差多少分，以及"逐条精挑"相比"全程无脑用那个全局最强的档"能多拿多少分：

| benchmark | 最优 − 次优 | oracle 质量 | 固定用最强档 | **能多拿的分** |
|-----------|------:|------:|------:|------:|
| geneval2 | 0.098 | 0.466 | 0.332 | 0.134 |
| corebench | 0.045 | 0.571 | 0.514 | 0.057 |
| wise | 0.043 | 0.866 | 0.759 | 0.107 |
| coco | 0.015 | 0.975 | 0.951 | 0.024 |

逐条精挑能多拿的，只有零点零几到零点一几分——这点差距甚至比质量分本身的噪声还小。也就是说，就算**完美**地逐条路由，相比"无脑固定用最好那个模型"也只多拿 0.024~0.134 分；而在这么窄的空间里，预测器只要稍微猜错一点，选择立刻翻车，这点收益马上就没了。

**(d) 合起来的后果：预测器根本认不出哪个是最优模型。** 直接看"猜中最优档"的命中率（这里不管成本，纯看质量预测准不准）：

| benchmark | TFMLP 命中率 | KNN 命中率 | 无脑猜多数$^\dagger$ | 瞎猜（1/5） |
|-----------|-----------:|---------:|--------:|-----:|
| geneval2 | 0.191 | 0.225 | 0.264 | 0.20 |
| corebench | 0.161 | 0.176 | 0.277 | 0.20 |
| wise | 0.177 | 0.183 | 0.233 | 0.20 |
| coco | 0.136 | 0.205 | 0.312 | 0.20 |

$^\dagger$ "永远选那个全局最常赢的档"。

会学习的预测器，命中率**跟五选一瞎猜（20%）差不多、甚至更低，而且每个 benchmark 都比"无脑永远选最常赢的那档"还差**。更麻烦的是，它一旦选错，平均要亏掉的分（本可以拿到却没拿到的）有 0.070（coco）到 0.249（geneval2）之多，远大于逐条路由本来能多拿的那点分。这就是第 2 节里它们输给 LP 的根本原因：LP 把预算稳稳花在全局较强的档上，不会付"很自信但猜错了"的代价；而学习式路由器却照着一个根本不存在的信号去行动，用一堆亏得很惨的错误选择，把本来就微薄的那点收益全赔了进去。

### 4. 两个实验对照，问题就清楚了

| | 实验一（同模型多步） | 实验二（多模型） |
|---|---|---|
| 要判断的方向 | 一条是非题（该不该上 tts） | 没有主导方向；五选一、还跟 prompt 强相关 |
| 最优档有多平均 | 集中（"值得上 tts"是一类清楚的 prompt） | 到最大值的 96%~99.6%（几乎全平均） |
| 最优 − 次优差距 | 在 tts 尾部拉得开 | 0.015~0.098（几乎打平） |
| 逐条排序对不对得上 | **正**（$+0.07$ 到 $+0.46$） | **≈0 或负**（$-0.38$ 到 $+0.10$） |
| 命中率 vs 瞎猜 | **高于**瞎猜（分类准确率 +0.8 到 +8.7） | **等于/低于**五选一瞎猜 |
| 学习式 vs 盲基线 | 学习式**赢** LP/OC | 学习式**输给** LP |

把两个实验放一起看，机制就一目了然：学习式的文生图路由器，只有当候选池里存在**一个清楚、粗粒度、差距够大的选择方向**时才有用——实践中就是"难 vs 易"，在本文里具体表现为"该不该上 tts"。一旦候选池换成几个能力相当、又没有这么一个主导方向的模型，"每条 prompt 最优选哪个"就变得又乱又平，预测器直接退化到瞎猜，这时候让它去看 prompt 内容还不如一个只管凑够预算的盲基线。

### 5. 结论

成本感知路由表面上的成功，其实靠的是模型池里存在一个**能力落差**，而且这落差表现为**一条单一的难度线**。当前这批文生图模型，作为一组能力相当的多模型组合，并没有这样一条线：唯一能可靠学到的区分，只有粗粒度的难易；一旦没有明确的难度梯度，路由器根本没法分类。这也就划出了学习式文生图路由在实际中管用的边界。
